# AGENTS.md

KOTavern — SillyTavern-style AI chat client for KOReader. This repo root **is** the plugin folder; the name `kotavern.koplugin` must never change (installs/updates depend on it). Plain Lua targeting KOReader's LuaJIT runtime (Lua 5.1 semantics); no package manager — only stdlib + KOReader libs (`ffi/blitbuffer`, `libs/libkoreader-lfs`, `socket`, `json`, `gettext`) + `curl` on device.

## Verification (mirror CI before pushing)

- Syntax (CI runs this on every .lua): `luajit -bl <file> > /dev/null` — LuaJIT is the reference interpreter, not lua/luac 5.4.
- i18n gate: `python3 tools/check_i18n.py` (from repo root). Every `_("…")` msgid in any .lua (`tools/` excluded) must have a non-empty `msgstr` in BOTH `locales/pt_BR.po` and `locales/es.po`, or CI fails. Ship new UI strings with both .po updates in the same change.
- UI smoke test (PLAN.md's merge gate): needs a KOReader checkout and its luajit; plain luajit won't load fonts/blitbuffer. Run it FROM KOReader's root — the harness prepends `common/?.lua;frontend/?.lua;...` to `package.path` relatively, so any other cwd dies on `ffi/loadlib`. KO_HOME points KOReader's data dir at a writable location (the install dir is often read-only), and the dir must already exist or `list_all_chats` raises on a missing `chats/`:
  ```
  mkdir -p /tmp/kotavern_ko/settings/kotavern/{chats,characters}
  cd /usr/lib/koreader && KO_HOME=/tmp/kotavern_ko SDL_VIDEODRIVER=dummy \
      ./luajit /path/to/kotavern.koplugin/tools/ui_smoke.lua
  ```
  Exit 0 = pass; the check count grows with each round (read the final line — 824 as of d14b814). PNGs land in `/tmp/kotavern_ui/` — use them for before/after on layout fixes.
- Release: push a `v*` tag; the workflow zips the repo (minus `.git`/`.github`/`data`) into `kotavern.koplugin-<ver>.zip` and attaches it to the GitHub release.

## Architecture

- Entry chain: `main.lua` (KOReader plugin entry; menu + nerd-font registration) → `kt_launcher.lua` (singleton) → `kt_app.lua` (app controller; global state + `SETTINGS_DEFAULTS`) → `ktui/app_view.lua` (canvas UI shell). The launcher has NO file-scope requires: `require("kt_app")` happens inside `Launcher.open`, so the 23-module app graph (plus the KOReader UI modules it pulls) loads when the plugin is opened, not during KOReader boot.
- Startup path (Kindle first launch): character cards are decoded with a lookup-TABLE base64 decoder (`kotaven_png.lua`; 35.7 ms → ~1 ms for a 66 KB card) and the PNG parser SKIPS the `IDAT` payload (only the `tEXt` chunks are read). The dashboard parses a card's metadata only when the card is PAINTED (`App:card_meta` / `App:apply_card_meta`, cached in `state._card_cache`); a name search or a `tag:` filter parses every card, because the filter needs the metadata, and the filter sheet warms the cache on demand.
- Scroll policy: every list page owns ONE scroll slot named after the page (`App:scroll_key()` returns the page name) and opens at offset 0 on every entry (`navigate`, `go_back`, `show_dashboard` → `App:_reset_page_scroll`; a sheet's `_saved_scroll` is dropped so it cannot restore the old offset). The chat keeps a per-chat slot (`chat_<id>`) and its bottom/new-message rule (the `999999` sentinel is never reset).
- `ktui/` = canvas UI framework adapted from ZenPM: `theme.lua` (palettes/fonts/metrics), `pages.lua` (every screen painter), `primitives/widgets/geom/scroll/sheets/modals`, `chat_theme.lua` (chat look: JSON theme + ST converter), `kthtml.lua` (MuPDF HTML rendering — the chat's HTML mode runs through it), `debug_stats.lua` (Debug header RAM/CPU). The old `theme_css.lua` (pure-CSS theme engine) and `uidsl.lua` are GONE (commits f013e1c / 92d6c13) — don't require them. `<data>/themes/` now holds only `pages/html_sandbox.html` (the user-editable HTML sandbox doc, rewritten on demand by `kthtml.lua`), not CSS theme files.
- Chat HTML rendering (`ktui/chat_bubbles.lua`; the sole normal renderer for message bodies): completed bodies and real streaming partials (assistant AND user), plus expanded reasoning, render through MuPDF in TWO stages — a layout-only MEASURE pass (`KtHTML.measure_body`: transparent CSS + `getSinglePageHeight()`, no bitmap) that caches the body height per message, and a PAINT pass that builds the tall bitmap ON DEMAND for the visible messages only (`html_widget_for`; band blit, scroll = 1 blit per band). Offscreen documents hold metadata only (no widget, no bitmap) and rebuild in place when they scroll back in; the layout cache skips unchanged messages. A body taller than `KtHTML.MEASURE_H` (65 536 px) has no measurement and falls back to the canvas renderer — no giant bitmap is ever built. System/narrator lines, the synthetic thinking pulse and MuPDF failure fallback stay on canvas. Re-expresses model markdown/HTML through an allowlist (ST DOMPurify parity): spoilers/`<details>` are tappable via `kt:spl:`/`kt:det:` links, reasoning state lives under `msg_key .. "|r"` (independent numbering).
- Book mode (`kt_book.lua` + `kt_book_session.lua`/`kt_book_reader.lua`): the DEFAULT and recommended chat mode (`chat_mode = "book"`; it left the Debug category — the picker lives in Appearance). Continuous per-message sections (no generated chapters), titled by speaker/local time/message number. Bodies with `<details>` or `||spoiler||` reuse `ChatBubbles.encode_html` with message/reasoning-qualified `kt:` links; reveal maps are session-only and native taps rebuild through the normal ReaderUI reload path. Emoji text nodes get scoped `.ktemoji` spans using bundled `assets/emoji-noto.ttf`, registered once with crengine (never the global fallback chain). Refresh policy: every refresh rebuilds the HTML, but the reload is SKIPPED when the generated HTML is byte-identical to the file on disk (`Book.read` vs `Book.build`) — provider/preset switches never reload the reader. The refresh kinds `"user"` and `"done"` carry the `#mN` anchor of the new message, and the reader position resolves as anchor → tail → previous xpointer → keep the current position; only an EMPTY book jumps to the cover (`choose_position` / `Session._test_choose_position`).
- Book look (`kt_book_theme.lua` + `ktui/pages.lua` `settings_book`/`settings_book_labels` + `kt_book_ui.lua`): the book's own theme (the List mode's chat themes do NOT apply to the reader). `BookTheme` = pure schema (normalize/sig/PRESETS/LABEL_KEYS/label) stored in `settings.book_theme`; the generated HTML carries `<meta name="kotavern-book-theme" content="<sig>">`, so any look change changes the bytes and forces the reload. Typography (font face/size/line spacing/margins) is written PER DOCUMENT through `DocSettings` for the generated book only (`font_face` unprefixed, `copt_font_size`/`copt_line_spacing`/`copt_font_base_weight`/`copt_h_page_margins`) — the global reader settings and the user's real books are never touched, and the write happens in the reload window (after the old reader flushed its position). The book mode CANNOT show canvas pages over the reader: the knobs it needs while the reader is up live in the native `BookUI.book_appearance` dialog.
- Root `kt_*.lua` domain modules: `kt_client.lua` (OpenAI Chat Completions; LuaSocket sync + background-curl streaming), `kt_storage.lua` (JSON settings/presets, SillyTavern PNG cards with ccv3 JSON in the tEXt chunk, `.jsonl` chats; mtime-keyed read cache — page painters re-read per paint), `kt_models/kt_world_info/kt_regex_engine/kt_backup/kt_update/kt_book_theme`, `kt_i18n.lua` (installs pt_BR/es into KOReader gettext).
- Self-update (`kt_update.lua` + `kt_app.lua`): the plugin checks for updates in the BACKGROUND when it opens (detached curl + `UIManager` poll, never in the paint path), at most once per 24 h (`update_checked_at`/`update_snooze_until`/`update_skip_version` in the settings). A failed check stays SILENT. The prompt is a native `ButtonDialog` (`Modals.build_update_prompt`) with three actions: update now / remind me later / cancel (cancel suppresses that exact tag). The manual check stays synchronous (`Update.check`). "What's new" (`release_notes` page) reads the cached notes (`update_notes_cache`): the release body on stable, the commits since the installed commit on Artifact.
- `kotaven_*.lua` = low-level helpers (PNG encode/export/util) ported from the old kotaven.koplugin.

## Conventions & gotchas

- Filenames are deliberately `kt_`-prefixed / under `ktui/`: require names must never collide with KOReader core or other plugins. Don't add bare `util.lua`, `theme.lua`, etc. at root.
- Never use `_` as a variable/index name (`for _, x in ipairs(...)`): it shadows gettext's `_()` in nested closures → "attempt to call upvalue '_'" crash (fixed once in 33c14bb; smoke has a self-check).
- Lua patterns have NO `(group)?` optionals and no `%1` backreferences in `match` — they fail SILENTLY. Use `%f[^%w]` frontiers for tag-name boundaries (see `chat_html_allowlist`), and remember `[dD][hH]` matches TWO positions (`[dDhH]` is one).
- Hitbox dispatch is LAST-registered-wins (reverse order): an overlapping box must be registered AFTER the broader one to receive taps (e.g. the favorite star must come after the row hit — see `ktui/cards.lua`). Disabled rows/actions must register NO hits at all.
- Assets are generated, not hand-edited: `lua tools/gen_assets.lua` (SVG icons, run from repo root), `tools/subset_nerd_font.sh` (pyftsubset), `tools/merge_emoji_font.py` (regenerates `assets/sans-x-*.ttf` = NotoSans+NotoEmoji merged — MuPDF does NO per-glyph font-family fallback, so the chat faces carry every glyph in ONE cmap; requires fonttools), `tools/gen_debug_banner.py` (pre-composites GIF frames — KOReader's giflib can't play delta-encoded GIFs; see `ktui/gifanim.lua`). `assets/emoji-noto.ttf` ships as-is (OFL): the merge source for the chat font faces.
- `PLAN.md` and `API_CONNECTIONS_PROMPT.md` are gitignored internal notes; `PLAN.md` (Portuguese) is the running plan/changelog — new work gets a dated section with checkboxes. Commits and code comments are in English.
- Version lives in two synced places: `VERSION` and `kt_constants.lua`'s `VERSION` — bump both together (see commit 6549740). `_meta.lua` stays at 0.1.0.
- `data/` is per-device runtime data: never commit, never ship.
